# Keyword Analyzer — Deployment Knowledge Base

Everything needed to deploy, configure and operate the tool. One repository,
two independently deployable Render services.

- **Repository:** `roy-sub/Keyword-Research-Intent-Analyzer-Backend`
  (GitHub reports it has moved to `roy-sub/Keyword-Research-Intent-Analyzer`;
  the old URL still redirects, but update your remote when convenient).
- **Branch deployed:** `main`
- **Blueprint:** `render.yaml` at the repo root — deploys both services.

---

## 1. Architecture

```
   Browser
      │  loads the UI
      ▼
  keyword-analyzer-web          Render Static Site   (rootDir: frontend/)
  index.html · styles.css · app.js
  config.js  ← generated at build time from API_BASE_URL
      │
      │  XHR with X-Access-Key, cross-origin
      ▼
  keyword-analyzer-api          Render Web Service   (rootDir: backend/)
  FastAPI · uvicorn · Python 3.11
      │
      ├── Google autocomplete   (37 paced sequential queries)
      └── AI chain              Claude → OpenAI → Gemini
```

The two services are wired to each other by `fromService` in the blueprint,
so **neither URL has to be known in advance**:

- the web service receives the API's hostname as `API_BASE_URL`, which
  `frontend/build.sh` turns into `config.js` at build time;
- the API receives the web service's hostname as `ALLOWED_ORIGINS`, which the
  backend promotes to `https://<host>` for CORS and the API-key gate.

> **Do not rename the Render services.** `keyword-analyzer-api` and
> `keyword-analyzer-web` are infrastructure ids referenced by `fromService`.
> Renaming them orphans the deployed services and creates new ones.

## 3. Backend environment variables

Read through `pydantic-settings` from the environment, falling back to
`backend/.env`. **Startup fails loudly on a missing required value** rather
than booting into a broken state.

### Mode

| Variable | Default | Notes |
|---|---|---|
| `MODE` | `dev` | `dev` or `prod`. **Set to `prod` on Render.** |

`MODE=prod` enforces `ALLOWED_ORIGINS` exactly, requires `API_KEY` for
callers outside those origins, and disables `/docs`, `/redoc` and
`/openapi.json` (they return 404).

### Access

| Variable | Default | Notes |
|---|---|---|
| `ADMIN_USERNAME` | `admin` | The single admin login. There are no other accounts. |
| `ADMIN_PASSWORD` | **required** | No default. Startup fails without it. Use a long random value. |
| `SESSION_TTL_HOURS` | `12` | How long an issued session token stays valid. |
| `API_KEY` | **required in prod** | Guards the API against callers outside the app. |
| `ALLOWED_ORIGINS` | empty | **Required in prod.** Comma-separated origins allowed to call this API. A bare hostname is promoted to `https://<host>`. |

### AI providers

Tried in order. At least one key must be set; an unset provider is skipped
rather than failing the chain. If **all** configured providers fail, the API
returns 502 with one curated reason per provider — never an upstream body,
never a key.

| Variable | Default | Notes |
|---|---|---|
| `AI_PROVIDER_ORDER` | `anthropic,openai,gemini` | Order to try. Unknown names ignored. |
| `AI_TIMEOUT_SECONDS` | `120` | Per-attempt timeout, applied to each provider separately. |
| `MAX_KEYWORDS_IN_PROMPT` | `600` | Prompt cap; truncation is noted in the prompt itself. |
| `ANTHROPIC_API_KEY` | — | https://console.anthropic.com/settings/keys |
| `ANTHROPIC_MODEL` | `claude-sonnet-5` | Stronger: `claude-opus-5`. Cheaper: `claude-haiku-4-5`. |
| `OPENAI_API_KEY` | — | https://platform.openai.com/api-keys |
| `OPENAI_MODEL` | `gpt-5.4-mini` | Compact tier, 400K context. Stronger: `gpt-5.4`. |
| `GEMINI_API_KEY` | — | https://aistudio.google.com/apikey |
| `GEMINI_MODEL` | `gemini-3.8-flash` | **`gemini-2.5-flash` is retiring — do not use it.** |

### Collection

| Variable | Default | Notes |
|---|---|---|
| `SUGGEST_LANG` | `en` | Autocomplete `hl`. |
| `SUGGEST_COUNTRY` | `us` | Autocomplete `gl`. |
| `SUGGEST_DELAY_SECONDS` | `1.0` | Pause between requests, plus up to 30% jitter. |
| `SUGGEST_TIMEOUT_SECONDS` | `5.0` | Per-request timeout. |
| `SUGGEST_MAX_RETRIES` | `2` | Backoff on timeouts, 429s and 5xx. |
| `SUGGEST_QUESTION_MODIFIERS` | `who,what,when,where,why,how` | |
| `SUGGEST_COMMERCIAL_MODIFIERS` | `best,buy,cheap,near me` | |

> Requests run **strictly sequentially, never concurrently.** This is a
> deliberate requirement, not an implementation accident. Raising
> `SUGGEST_DELAY_SECONDS` reduces throttling; lowering it invites it.

### Limits, cache, logging

| Variable | Default | Notes |
|---|---|---|
| `RATE_LIMIT_MAX_SEARCHES` | `10` | Global, not per-user. |
| `RATE_LIMIT_WINDOW_MINUTES` | `60` | Sliding window. |
| `CACHE_TTL_MINUTES` | `1440` | A cache hit costs no quota and makes no upstream call. |
| `CACHE_MAX_ENTRIES` | `50` | LRU beyond this. |
| `LOG_LEVEL` | `INFO` | |

## 4. Frontend configuration

Exactly one variable.

| Variable | Set by | Notes |
|---|---|---|
| `API_BASE_URL` | the blueprint, from the API service's host | `build.sh` writes it into `config.js`. A bare hostname is promoted to `https://<host>`; a trailing slash is stripped. |

`build.sh` **fails the build** when `API_BASE_URL` is missing — shipping a UI
that silently calls `localhost` is worse than not shipping it.

The committed `frontend/config.js` holds the **local development** default
(`http://localhost:8000`). Editing it does not affect a deploy; it is
overwritten on every build.

## 5. Deploying to Render

### First deploy

1. **New → Blueprint**, point it at the repository, branch `main`. Render
   reads `render.yaml` and proposes both services.
2. Render prompts for every value marked `sync: false`. Provide:
   - `ADMIN_PASSWORD` — long and random
   - `API_KEY` — long and random
   - `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `GEMINI_API_KEY` — at least one
3. Apply. Both services build. The API's health check is `/api/health`.

Nothing else needs configuring: `API_BASE_URL` and `ALLOWED_ORIGINS` resolve
from each other automatically.

### Service settings already in the blueprint

| | `keyword-analyzer-api` | `keyword-analyzer-web` |
|---|---|---|
| Type | Web Service | Static Site |
| Runtime | Python 3.11.9 | static |
| Root dir | `backend` | `frontend` |
| Build | `pip install -r requirements.txt` | `./build.sh` |
| Start | `uvicorn app.main:app --host 0.0.0.0 --port $PORT` | — |
| Publish dir | — | `.` |
| Health check | `/api/health` | — |

Static-site headers set by the blueprint: `X-Content-Type-Options: nosniff`,
`Referrer-Policy: strict-origin-when-cross-origin`, and
`Cache-Control: no-store` on `/config.js` so a redeploy is never served a
stale API URL.

### Rotating a secret

Change it in the Render dashboard for `keyword-analyzer-api` and redeploy
that service only. The frontend does not hold any secret.

## 6. API contract

All bodies are JSON. Auth is `X-Access-Key: <token>` unless noted.

| Route | Auth | Purpose |
|---|---|---|
| `GET /` | none | Service descriptor |
| `GET /api/health` | none | Render's health check |
| `POST /api/login` | none | `{username, password}` → `{ok, access_key}` |
| `POST /api/logout` | yes | Invalidates the token |
| `GET /api/status` | yes | Quota, window, pacing, expected query count |
| `POST /api/analyze` | yes | `{topic}` → the full result payload |
| `POST /api/export/report.pdf` | yes | The report payload → `application/pdf` |

`/api/export/report.pdf` takes the report the client already holds rather
than a run id, so it **costs no quota, makes no upstream call and stores
nothing**. Re-running the analysis to export it would burn a quota slot and
could return different prose than the one on screen.

Error statuses from `/api/analyze`: `400` bad topic, `401` bad key, `429`
quota exhausted (with `retry_after_seconds` and a `Retry-After` header),
`502` no suggestions or all providers failed, `504` run timed out. **No key,
traceback or upstream response body ever appears in `detail`.**

## 7. Operational notes

- **Health stays responsive during a run.** The collection pipeline never
  blocks the event loop; `/api/health` answers in ~1 ms throughout a full
  37-query run. PDF rendering runs on a worker thread for the same reason.
- **Partial results are honest.** Every failed query is logged with its
  status and returned in `failed_queries`. Some failing → partial results
  with accurate counts. All failing → 502.
- **Sessions are in memory.** A restart or a second instance invalidates
  issued tokens; users sign in again. Keep the API at one instance unless you
  move sessions to shared storage.
- **The rate limit is global**, not per-user — it protects the upstream quota,
  not individual fairness.
- **Secrets never reach the repo.** `.gitignore` covers `.env`. Nothing is
  logged that could reconstruct a credential.

## 8. Downloads

Downloads live in the tab that owns the data, not in a header menu.

| Tab | Formats | Default | Produced by |
|---|---|---|---|
| Intent report | PDF, Markdown | **PDF** | PDF server-side; Markdown in the browser |
| Keywords | TXT, JSON, CSV | **TXT** | All three in the browser |

- **TXT** — the plain keyword list, one per line, under two `#` comment lines
  of provenance.
- **JSON** — keeps each keyword's `sources` and `types`.
- **CSV** — written with a UTF-8 BOM, so Excel does not mojibake non-ASCII
  keywords.
- **Markdown** — the report plus a provenance header.
- **PDF** — typeset by ReportLab with running heads, real pagination and
  ruled tables. If the call fails the UI points at the Markdown download,
  which needs no backend.

## 9. Verifying a deploy

```bash
# 1. Health (no auth)
curl https://keyword-analyzer-api.onrender.com/api/health
# → {"status":"ok"}

# 2. Docs must be closed in prod
curl -o /dev/null -w '%{http_code}\n' \
  https://keyword-analyzer-api.onrender.com/docs
# → 404

# 3. Sign in
TOKEN=$(curl -s https://keyword-analyzer-api.onrender.com/api/login \
  -H 'Content-Type: application/json' \
  -H "X-API-Key: $API_KEY" \
  -d '{"username":"admin","password":"<ADMIN_PASSWORD>"}' \
  | python3 -c 'import sys,json; print(json.load(sys.stdin)["access_key"])')

# 4. Quota and run parameters
curl -s https://keyword-analyzer-api.onrender.com/api/status \
  -H "X-Access-Key: $TOKEN"

# 5. The UI must point at the API, not localhost
curl -s https://keyword-analyzer-web.onrender.com/config.js
```

Then open the web service, sign in, and run one topic end to end.

## 10. Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| Sign-in fails with correct credentials | CORS preflight rejected — the origin you are browsing from is not in `ALLOWED_ORIGINS` | Browse the exact origin listed. Locally use `http://localhost:5173`, **not** `0.0.0.0:5173`. |
| `Could not reach the server` | `config.js` points at the wrong origin, or the API is asleep | Check `/config.js`; wake the API with `/api/health`. |
| Startup crash on boot | A required variable is missing | The log names it. Usually `ADMIN_PASSWORD`, or `API_KEY`/`ALLOWED_ORIGINS` under `MODE=prod`. |
| All three providers fail | No key set, or all keys invalid/over quota | The 502 body names one reason per provider. |
| Many throttled queries | Google is rate-limiting | Raise `SUGGEST_DELAY_SECONDS`. Partial results are still real data. |
| PDF download shows a note | The export call failed | Markdown still works. Check the API log for `pdf render failed`. |
| Report renders as plain text | `marked`/`DOMPurify` did not load from the CDN | A banner says so. Keyword data is unaffected. |
| Fonts look like the system stack | Google Fonts unreachable | Layout holds — sizes and spacing are tokens, not font-dependent. |

## 11. Design system (for future changes)

Documented in full in `frontend/README.md`. The short version:

- **Light only, monochrome.** Black, white and grey. No dark palette, no
  `prefers-color-scheme` block.
- **Exactly one hue.** `--c-live` appears on the run progress bar and the
  pulsing *Running* dot and nowhere else, so colour means *this is moving*.
- **Intent classes read by value, not colour** — four steps down the ink
  ladder, which also survives greyscale printing and colour blindness. Fill
  and ink are separate tokens: bars need the greys spread wide, tag text
  needs them dark enough to clear 4.5:1.
- **Geist and Geist Mono**, from Google Fonts.
- **Radii 3/5/8/10px, no pills.** Hairline separation first; shadow only
  where something floats.
- **Change a token, not a component.** `styles.css` is tokens → primitives →
  regions, in that order.

All text pairs meet WCAG AA, verified by computing ratios from the tokens.

## 12. Tests

```bash
cd backend && source .venv/bin/activate && pytest -q
# → 109 passed
```

The suite mocks all HTTP; it never calls Google or any AI provider. Two
tests guard the frontend/backend seam: every `apiUrl("…")` call site in
`app.js` must map to a real route, and `mock-response.json` must still
validate against the response model — so the fixture and the client cannot
silently drift from the API.
